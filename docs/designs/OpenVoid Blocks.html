Blocks

Skeletal components.

A block is a skeletal component or organisational structure — comparable to a card element or a button element. Blocks manage their own internal context and don't know about their surroundings.

Blocks are the atoms. Things like the Composer, the Artifact Card, and the Stack Detection Card are compositions of blocks — you'll find those in Compositions.

Inputs

4 blocksAll inputs share the same inset-border focus model. Never use outline: auto — always suppress and replace with the accent focus ring.
Text Field .field

Standard single-line input. 36px height, card background, 7px radius, inset box-shadow border. Focus replaces the shadow with a deeper line + the accent focus ring (0 0 0 4px --accent-soft). Disabled at 45% opacity.

Always suppress the browser's default outline. Use the inset-shadow + focus-ring pattern instead. Never use a visible border — the box-shadow keeps the border participates in the focus transition cleanly.

--card--line--r-sm--accent-soft--ink-3
Mono Text Field .field.mono / .gh-field

Same geometry as Text Field but uses JetBrains Mono at 13px / 500. Used wherever the value is an identifier: a repository slug, a branch name, a domain name, an env var key. Same focus ring behaviour.

Mono only for identifiers. Never use for natural-language input — switch back to sans-serif the moment the field accepts human prose.

--font-mono--card--line--r-sm
Textarea .composer-textarea / textarea

Multi-line input. Inherits the same inset-border + focus-ring model as Text Field. resize:none — height is controlled programmatically via auto-grow (set height:auto on input, then reassign scrollHeight). Used bare inside the Composer composition; the Composer card provides the visual container.

Min-height 88px standalone; 118px inside the Composer. Max-height 360px — beyond that the textarea scrolls internally. Never expose the native resize handle.

--font-sans--ink-4--accent-soft--r-sm
Select .gh-branch / select

30px native <select> with appearance:none and a custom SVG chevron via background-image. Same inset-border as other inputs. Used for branch selection in the GitHub Input Panel and for stack override dropdowns. Keeps Inter / ink-2 text.

Use native <select> — not a custom dropdown — unless the option list requires rich content (icons, grouped sections). Native select is accessible and works on mobile without extra JS.

Drop Zone .drop

Full-width dashed upload target. A single interactive surface — not a composition. Three states: default (dashed --line border), hover (border darkens to ink-3), dragging (accent border + accent-soft fill + focus ring). Click opens file picker; drag-and-drop accepted anywhere on the document.

Accepts .zip only. The dragging state is applied by JavaScript on dragenter/dragleave/drop. Drag depth counter prevents flicker on child hover.

Terminal

1 blockThe only dark surface in the system. Used exclusively on the Provisioning screen.
Boot Log .terminal

Dark (#0E0E0E) surface, JetBrains Mono 12px / 1.7 line-height. Four text colour classes: .dim for comments/metadata, .ok for success lines (green), .inf for neutral lines (off-white), .acc for highlights (warm amber). No spinner characters — use the Breathing Dot (Eyebrow Pill) above the terminal for live state.

Never put interactive elements inside the terminal. It is read-only output. Scrolls vertically inside a constrained container — max-height should be set by the parent composition.
