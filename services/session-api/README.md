# @openvoid/session-api

The HTTP API in front of the per-session Pod lifecycle. Reads Kubernetes
Secrets at boot (no live polling), issues `kubectl`-equivalent calls
through `@kubernetes/client-node`, and returns the OpenAPI shape
generated by `@openvoid/protocol`.

The Hono router lives in `src/routes/sessions.ts`. The K8s manifest
builder (constants, Pod/Service/Ingress shapes, the `K8sSessionOps`
class) lives in `src/k8s/client.ts`. Boot wiring lives in
`src/server.ts`.

## Local development

Run the whole stack through Tilt:

```
tilt up
```

The Session API hot-reloads on changes under `src/` (tsx watch via the
dev container). Direct unit tests:

```
pnpm --filter @openvoid/session-api test
pnpm --filter @openvoid/session-api typecheck
```

## Environment

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `4000` | HTTP listen port. |
| `OPENVOID_DOMAIN_BASE` | `127.0.0.1.nip.io` | Suffix for per-session ingress hosts. DOKS overrides via env; v1.5 chart overrides via values. |
| `OPENVOID_URL_SCHEME` | `http` | Scheme on the URLs the API surfaces to landing. `https` on DOKS once cert-manager is wired. |
| `OPENVOID_LANDING_ORIGIN` | `http://app.127.0.0.1.nip.io` | Permitted CORS origin for landing-page calls. |
| `OPENVOID_PLATFORM_GITHUB_ORG` | — (required for new-app entry point) | Name of the platform-owned GitHub org. The Session API creates per-app repos under this org for the new-app flow. The PAT for this org lives in the `github-platform-creds` Secret (see "Boot-time Secret reads"). |
| `OPENVOID_STUB_IMAGE` | — | When set, overrides the per-session main image. Phase 5 demos set this to `nginx:alpine` to bypass OpenCode for lifecycle-only debugging. |

## Boot-time Secret reads

The Session API does not poll Secrets — it reads each one once at boot
via the Kubernetes API. If a required Secret is missing or unreadable,
the process exits with a clear log line and the Deployment surfaces the
failure via CrashLoopBackOff.

| Secret | Namespace | Key | Used for |
|---|---|---|---|
| `opencode-server-password` | `openvoid-sessions` | `password` | Builds the `Basic <base64(opencode:password)>` header that ingress-nginx injects on per-session agent ingresses (no browser password prompt). |
| `github-platform-creds` | `openvoid-sessions` | `token` | Authenticates `octokit.repos.createInOrg` against `OPENVOID_PLATFORM_GITHUB_ORG` when handling `POST /sessions { mode: "new-app" }`. Same token is mounted onto per-session `workspace-init` + `git-finalizer` containers for the seed push and on-exit push. |

Both Secrets live in `openvoid-sessions` rather than `openvoid-system`
because the per-session containers that consume them also live in
`openvoid-sessions`, and Kubernetes does not support cross-namespace
`secretKeyRef`. The Session API itself runs in `openvoid-system`; the
`session-api-pods` Role in `openvoid-sessions` grants `get` on these two
Secret names by `resourceName` (least privilege).

Rotation: regenerate the Secret value, `kubectl apply` the manifest,
then `kubectl rollout restart deployment session-api -n openvoid-system`
so the new value is picked up at next boot.
